## Fluxo da V2

```text
código Python
    ↓
preprocessamento + AST
    ↓
LLM aponta função/módulo, categoria e expressão
    ↓
AST verifica se a expressão existe no código executável
    ↓
candidato aceito
    ↓
ESBMC nativo, quando aplicável
    ↓
verbatim-driver
    ↓
síntese escalar como fallback
    ↓
validador determinístico do harness
    ↓
ESBMC executa o harness
    ↓
grounding diferencial para resultados esperados
    ↓
classificação e métricas
```

### Função de cada etapa

1. O preprocessamento usa AST para separar funções. Arquivos sem função geram
   uma unidade `module`, usada para casos como constantes no nível do módulo.

2. A LLM recebe o código e retorna uma hipótese estruturada: unidade, categoria,
   expressão suspeita e evidência.

3. O AST verifica apenas se a expressão retornada existe como código executável.
   Ele não classifica o bug e não prova que a categoria está correta.

4. O caminho nativo usa o ESBMC diretamente na função real, quando há suporte
   suficiente para transformar os parâmetros em valores simbólicos.

5. O `verbatim-driver` preserva a expressão e o corpo real da função. A LLM
   troca somente as entradas por `nondet_*()` e cria o driver simbólico.

6. A síntese escalar é o fallback. Ela abstrai a expressão em um harness menor,
   mas tem maior risco de perder a relação com o bug original.

7. O validador rejeita harnesses que não sejam executáveis ou que usem recursos
   incompatíveis, como imports proibidos, nomes indefinidos, loops inadequados,
   numpy/pandas ou propriedades vazias.

8. O ESBMC decide se encontrou uma violação, não encontrou, ficou inconclusivo
   ou não conseguiu gerar uma propriedade.

9. Para `incorrect_result` e `assertion_violation`, o grounding diferencial
   exige uma expectativa independente. Um `assert` isolado pode ser executado,
   mas é classificado como `confirmed_unverified`.

## Diferença entre as duas avaliações

### Síntese isolada

Com `--v2-stage synthesis`, as hipóteses vêm do gabarito. Essa etapa mede:

- se a LLM gera um harness válido;
- se o harness representa a expressão indicada;
- se o ESBMC consegue confirmar a propriedade;
- qual tier funcionou: nativo, driver ou escalar.

Ela não mede se a LLM encontrou o bug sozinha.

### End-to-end

Com `--v2-stage end-to-end`, a LLM recebe os arquivos de detecção e precisa
encontrar sozinha a unidade, a categoria e a expressão. Depois, os candidatos
passam pelo mesmo pipeline de AST, harness e ESBMC.

Essa é a medição principal do método completo.
