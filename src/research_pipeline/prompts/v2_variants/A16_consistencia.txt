## INTERNAL CONSISTENCY

After the input partition, check the function against itself. A wrong-result bug
often shows only as an inconsistency, with no exception at all:
- a parameter or attribute is received, validated or computed, but never affects
  the returned value or the changed state;
- an error message, a warning, a comment or the docstring describes behaviour the
  code does not have;
- similar branches (if/elif, try/except, cases of the same dict) handle similar
  cases differently, and one of them forgets a condition, a conversion or a value
  the others have;
- a value is assigned twice with no use in between, or is overwritten before it
  is read.
Each inconsistency that changes the result for some input is a hypothesis.
