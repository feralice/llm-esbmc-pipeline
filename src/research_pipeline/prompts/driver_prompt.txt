You turn a hypothesized bug in a real Python function into an ESBMC-Python
harness by keeping the smallest RUNNABLE SLICE of the real code around the bug
verbatim, and writing only the symbolic driver around it. This is the
"verbatim-slice" method, adapted from the reference PoC
(github.com/lucasccordeiro/vllm, harness/).

It is NOT reconstruction. You do not rewrite the suspect expression from fresh
variables. You copy the real line(s) and replace only the operands that ESBMC
cannot model.

You are given:
- the source of one real Python function,
- a hypothesis: a bug category and the exact expression suspected to be unsafe,
- the exact list of preconditions the real function enforces on its inputs,
- for wrong-result categories, the intended (fixed) behaviour when known.

Produce ONE Python file following every rule below. ALWAYS produce a harness --
there is no "return nothing" option. If the function is a method, a
library-heavy blob, or anything else, you still slice out the bug line and
model its object/container operands as nondet.

RULES

1. THE SLICE. Copy, verbatim, the suspect expression and the few lines that
   compute its operands. Same operators, same order, same call names
   (`len`, `int`, `abs`, `isinstance`, ...). Then:
   - every operand that comes from `self.x` / `obj.attr` / `a[i]` / a call to
     something not given to you / an unresolved name -> replace it with a
     parameter fed a fresh nondet_*() of the plausible type. Add a one-line
     comment: `# real: <the original operand>`.
   - DROP everything the suspect expression does not need: docstring, unrelated
     branches, logging, I/O, the rest of the body.
   - Keep the real arithmetic. `x[ind] - x[ind-1]` becomes `a - b` (the
     subtraction stays; the subscripts go). `self.index == PERIOD` becomes
     `index_tag == PERIOD` (the comparison stays). Never collapse `a - b` into a
     single nondet -- that deletes the operator the bug lives in.

2. Put the slice in a small function (any name, e.g. `slice_model`), fully
   type-hinted (params + return). No new loops; keep a real loop only if the
   bug is inside it and its bound is small.

3. Symbolic inputs use EXACTLY these bare names: nondet_int(), nondet_float(),
   nondet_bool(), nondet_str(). NOT nondet_uint, NOT __ESBMC_nondet_int. Do NOT
   import them and do NOT define them -- a runtime `def nondet_int(): ...`
   shadows the intrinsic and makes the whole run vacuous (0 VCCs). Never write
   `import` or `from ... import`.

4. Driver shape. Define the slice function, then `main()` that: binds one fresh
   nondet_*() per parameter; constrains them with `__ESBMC_assume` (rule 5);
   calls the slice and BINDS the result (`result = slice_model(...)`); asserts a
   property of `result` (rule 6). Then call `main()` at module level -- required,
   the nondet_* / __ESBMC_assume intrinsics only register when execution starts
   at module level.

5. PRECONDITIONS as `__ESBMC_assume`, nothing else.
   - Encode EXACTLY the allowlist preconditions and the invariants the real
     caller guarantees. A bound the function does not check and the caller does
     not guarantee is over-restriction and hides the bug.
   - Add ONE loose magnitude bound per numeric input so the search terminates:
     `__ESBMC_assume(0 <= x)` and `__ESBMC_assume(x <= 1073741824)` (1<<30); use
     1<<10 instead only if the property multiplies two symbolic inputs. Keep it
     wide; never tie it near the value that triggers the bug.
   - For every nondet_float(), add `__ESBMC_assume(x == x)` to exclude NaN.

6. THE PROPERTY is a plain `assert`. No `__ESBMC_cover`, no message marker.
   - division_by_zero: `assert <divisor> != 0` right before the division, where
     `<divisor>` is the real divisor sub-expression (kept verbatim per rule 1).
     `//` and `%` on ints are also checked implicitly by ESBMC.
   - out_of_bounds: bind the chained check to a name -- `ok = 0 <= idx < n` then
     `assert ok` -- before the access.
   - integer_overflow: compute the value, assert it stays in range.
   - assertion_violation / incorrect_result: the function returns the WRONG
     value for a valid input. Assert the postcondition the contract/docstring
     promises, computed from the inputs (e.g. ceiling division:
     `assert q * b >= a and (q - 1) * b < a`). Given the fixed behaviour, model
     it as a separate expression on the SAME inputs and `assert result ==
     expected`. NEVER assert against a hardcoded literal.
   - type_mismatch / none_misuse (the real line is `isinstance(x, T)` /
     `assert x is not None` / similar): the value comes from outside (a `.get()`,
     a parsed field, a caller argument) and the bug is that it can be the WRONG
     type / None. NEVER type-hint the stand-in as T and then check
     `isinstance(stand_in, T)` -- in ESBMC-Python a value declared T can only be
     T, so that check is always true and proves nothing. Instead model the
     value with a DIFFERENT nondet type plus an explicit tag, and check the tag:
     `kind: int = nondet_int()` ; `__ESBMC_assume(0 <= kind <= 2)` (0 = the
     expected type, 1/2 = other types the source could produce) ;
     `is_expected_type: bool = kind == 0` ; `assert is_expected_type`. The
     assert fails exactly when the external value was not the expected type --
     the real bug.
   - The assert must reference `result` (or a value derived from it).

7. Header comment: name the real function (module path + line if given), the
   category, and one line each: what every `__ESBMC_assume` encodes, what the
   assert checks, and which operands were turned into nondet.

8. SPURIOUS PATTERNS to avoid (docs/esbmc/python_frontend_reference.md sec 6):
   `re.match`/`search` return bool not Optional[Match], so `if m is None:` is
   dead; a string method on a symbolic receiver (`.removeprefix`, `.center`,
   `.format`, `.partition`, `.splitlines`) degrades to nondet, so an assert on
   its result proves nothing; `isinstance(x, T)` on a stand-in typed T is always
   true. Keep the real operators; turn the untrusted operand into a nondet of a
   DIFFERENT shape and check that.

OUTPUT

Return only the harness, inside a single ```python fenced block. Nothing else.
