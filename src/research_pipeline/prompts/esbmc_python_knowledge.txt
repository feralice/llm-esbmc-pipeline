ESBMC-PYTHON FACTS (ESBMC 8.5; sources: esbmc website/content/docs/python/limitations.md, esbmc-plugin language-specific.md, esbmc-python-guide skill). Apply them when writing the rewrite and the driver.

Types
- Every parameter and every return of every function and method needs an annotation. A missing return annotation gives "ERROR: Return type undefined"; use "-> None" when nothing is returned.
- Containers need precise element types: list[int], list[str], list[dict[str, int]], dict[str, int], tuple[int, str]. A bare "list" or "dict" makes indexing fail ("list indices must be integers or slices, not str").
- Unions of scalars collapse to the widest (float > int > bool); unions mixing a scalar and a container are opaque. Prefer one concrete type. Optional[T] / "T | None" is kept.
- Any-typed functions only support int/float/bool results.

Inputs in the driver (bare intrinsics, no import)
- Scalars: nondet_int(), nondet_float(), nondet_bool(), nondet_str().
- Containers: write a literal of the exact shape with nondet leaves, annotated precisely, e.g.
    items: list[dict[str, int]] = [{"date_obj": nondet_int()}, {"date_obj": nondet_int()}]
    rows: list[list[str]] = [[nondet_str()], [nondet_str(), nondet_str()]]
  Keep them small (1 to 3 elements). An empty literal ([] or {}) is a valid concrete input too.
- None is a value: x: int | None = None, or choose with a nondet_bool() branch.
- Objects: obj = ClassName(...) with literal or nondet scalar arguments, then obj.method(...). A method cannot be the entry point by itself.
- nondet_float() includes NaN and Inf.

Supported / unsupported constructs
- for over range(), lists, strings, tuples; list/set/dict comprehensions (dict comprehension only over range(), a list of tuples or d.items()); for-else.
- Dicts: literals, d[k], d[k] = v, del, in, ==, keys/values/items, update, get, setdefault, pop, popitem, clear. Not copy().
- Sets: union/intersection/difference/issubset/issuperset/symmetric_difference/update; use operators instead of add/remove/discard.
- min/max: two-argument or single-list form; key= only for simple lambdas over constant lists. any()/all(): list literals only. sum(): int/float only. sorted(): int/float/str/tuples.
- str methods on non-constant strings: upper/lower/isdigit/isalpha/find/count/join are modeled; others (format, partition, splitlines, center, ...) return arbitrary values. "%" formatting with non-constant arguments is unsupported: use + concatenation or an f-string.
- re: only match/search/fullmatch, and the result is a bool (use "if m:", not "if m is None:"); no group() semantics.
- Imported modules are not modeled except a few (math, re, random basics, typing). numpy, os, binascii, logging, third-party packages: "Object ... not found". Replace only the call with an equivalent pure-Python expression in place when one exists (for example binascii.hexlify(b) -> manual hex loop); otherwise the case cannot be adapted: keep the rewrite and say so in assumptions.
- Walrus only in if/elif conditions and comprehension filters; lambda return type defaults to float.

Properties ESBMC reports by itself
- "division by zero" (for // and %; true division "/" of floats is NOT checked), "index out of bounds", "uncaught exception: <Name>" for any raised and uncaught exception (KeyError, IndexError, ZeroDivisionError, TypeError, AttributeError, ValueError, ...).
- int(s) on a non-numeric string and d[k] on a missing key raise on their own.
