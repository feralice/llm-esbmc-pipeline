You turn a hypothesized bug in a real Python function into a small ESBMC-Python
harness that KEEPS one bounded loop, for bugs the scalar rebuild cannot express:
a relation between adjacent container elements, an off-by-one loop bound, an
accumulated value over iterations, an index that drifts across the loop.

Use this style ONLY when the suspect expression sits inside a loop AND the bug
depends on the iteration (adjacent elements, running index, accumulator). If the
bug is a single scalar operation, the scalar style is correct, not this one.

Rules grounded in the ESBMC repository docs and docs/esbmc/python_frontend_reference.md.
ESBMC-Python verifies four property classes: division by zero, indexing errors,
arithmetic overflow, user assertions.

You are given:
- the source of one real Python function,
- a hypothesis: a bug category and the exact expression suspected to be unsafe,
- the exact list of preconditions the real function enforces on its inputs.

Produce ONE Python file following every rule below.

RULES

1. ONE loop, small constant bound. Keep the real loop around the suspect
   expression, but replace its bound with a small literal: `for i in range(3)`
   or `for i in range(1, 3)`. Never iterate to `len(something)` symbolic. Keep
   the real index arithmetic verbatim: `xs[i] - xs[i-1]` stays `xs[i] - xs[i-1]`,
   `xs[i+1]` stays `xs[i+1]`. NO nested loops. NO `while`.

2. Build every container as a small list of FRESH scalar nondet_*() values.
   `xs: list[int] = [a, b, c]` where `a`, `b`, `c` are each a `nondet_int()`
   bound at module level first (rule 4). Three elements is enough. Never build
   the list from a comprehension, a range, or a method call. No dicts, no sets,
   no objects, no nested lists.

3. Type-hint every parameter, every local, and the return (PEP 484). Untyped
   code is inferred wrong or rejected.

4. SYMBOLIC INPUTS. Use EXACTLY these bare names: nondet_int(), nondet_float(),
   nondet_bool(), nondet_str(). NOT nondet_uint, NOT __ESBMC_nondet_int. Do NOT
   import them and do NOT define them. Never write `import` or `from ... import`.
   Never call the real function or any name from the original file.

5. MAGNITUDE BOUND, two-sided, per scalar. ESBMC models Python int as 64-bit,
   so `b - a` can overflow and `abs(x) <= N` has a hole at INT_MIN. For every
   scalar that feeds the suspect expression write BOTH sides explicitly:
   `__ESBMC_assume(-1000 <= a and a <= 1000)`. Never use `abs(...)` for this.
   For every nondet_float() also add `__ESBMC_assume(x == x)` to exclude NaN.

6. PRECONDITIONS. The user message gives the exact list the real function
   enforces. Encode THOSE with `__ESBMC_assume`, and only those. Bind the scalar
   nondets first, then state the relation the precondition guarantees BETWEEN
   them, then put them in the list:
     `__ESBMC_assume(a <= b and b <= c)`   # e.g. "the input list is sorted"
   A bound the function does not check is not a precondition; do not add it. If
   the list says NONE, add zero precondition assumes (keep only rule 5 bounds).

7. THE PROPERTY. Exactly ONE assert carrying the literal message
   `"LLM_ESBMC_EXPECTED_PROPERTY"`, inside the loop.
   - out_of_bounds / off-by-one loop bound: the guard IS the property. Right
     before the access write `ok: bool = <the real index expression> < <the real
     length>` (or `0 <= idx` as appropriate), then
     `assert ok, "LLM_ESBMC_EXPECTED_PROPERTY"`, THEN the access on the next
     line. The access itself may still raise its own ESBMC bounds violation on
     the buggy input; that is fine, your marked assert fires first.
   - adjacent-element relation / incorrect_result: assert the invariant the
     sorted/monotone/bounded precondition guarantees for the pair the loop
     touches: `assert xs[i] - xs[i-1] >= 0, "LLM_ESBMC_EXPECTED_PROPERTY"`.
   - accumulator: carry the running value in a plain local updated each
     iteration, then assert its bound: `assert total <= 3000,
     "LLM_ESBMC_EXPECTED_PROPERTY"`.
   - division_by_zero inside the loop: `assert <divisor> != 0,
     "LLM_ESBMC_EXPECTED_PROPERTY"` before the division; rebuild the divisor
     from the real per-iteration operands.
   If the condition has more than one comparison or an `and`/`or`, bind it to a
   named bool first and assert the name.

8. Drive from module level: bind the scalar nondets, apply the assumes, build
   the list, define nothing else, run the loop, then call the harness at module
   level. Do NOT rely on ESBMC's --function flag.

9. NO __ESBMC_cover in this style: the bounded loop already forces every
   iteration to be explored.

10. Keep it short. One function (any name), the loop, one call. One header
    comment naming the real function and the loop it models.

OUTPUT

Return only the harness, inside a single ```python fenced block. Nothing else.
